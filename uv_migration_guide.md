# Руководство по миграции Python пакета на uv 0.8.2

Этот документ содержит пошаговое руководство и ключевые моменты, которые необходимо учитывать при миграции существующего Python пакета на систему управления зависимостями и сборки `uv` версии 0.8.2.

## 1. Анализ исходного состояния

Перед началом миграции необходимо проанализировать структуру и конфигурацию проекта.

*   **Найдите `pyproject.toml`**: Это основной файл конфигурации для современных Python проектов. Он содержит метаданные, зависимости и настройки системы сборки.
*   **Определите текущую систему сборки**: В секции `[build-system]` файла `pyproject.toml` указан текущий `build-backend` (например, `hatchling`, `setuptools.build_meta`, `poetry.core.masonry.api`). Это определяет, какие инструменты и конфигурации нужно будет заменить.
*   **Проверьте структуру исходного кода**: Обратите внимание, где находятся исходные файлы пакета. Наиболее распространенные варианты:
    *   `src/your_package_name/` (рекомендуемая структура)
    *   `your_package_name/` (в корне проекта)

## 2. Обновление `pyproject.toml`

Основное изменение заключается в замене системы сборки.

*   **Измените `build-backend`**:
    ```toml
    [build-system]
    requires = ["uv_build>=0.8.2,<0.9.0"]
    build-backend = "uv_build"
    ```
    *   `requires = ["uv_build>=0.8.2,<0.9.0"]` гарантирует, что будет использоваться совместимая версия `uv_build`.
    *   `build-backend = "uv_build"` указывает `uv` как инструмент для сборки дистрибутивов (wheel и sdist).

*   **Удалите устаревшую конфигурацию**: Удалите все секции, специфичные для старой системы сборки. Например, если использовался `hatch`, удалите секции `[tool.hatch]` и `[tool.hatch.build.targets.wheel]`.

## 3. Адаптация структуры проекта

`uv_build` по умолчанию ожидает, что исходный код пакета находится в директории `src/`. Если в вашем проекте исходники находятся в корне, возможны два пути:

*   **Рекомендуемый способ: Переместить в `src`**:
    1.  Создайте директорию `src`: `mkdir src`
    2.  Переместите директорию пакета в `src`: `mv your_package_name src/`
    3.  Проверьте, что структура стала `src/your_package_name/__init__.py`.

*   **Альтернативный способ: Настроить `uv_build`**:
    Если перемещение нежелательно, можно настроить `uv_build` на использование корневой директории. Это делается с помощью опции `--module-root`, но требует дополнительной настройки и не является стандартной практикой.

## 4. Обновление документации (`README.md`)

Важно обновить инструкции для пользователей, чтобы они знали, как устанавливать ваш пакет.

*   **Установка из репозитория (Git)**:
    *   **Для пользователей с `uv` и `pyproject.toml` (рекомендуемый способ)**:
        ```bash
        uv add git+https://github.com/your-username/your-repo.git@tag-or-branch
        uv sync
        ```
    *   **Для пользователей с `pip` или `uv` (прямая установка)**:
        ```bash
        pip install git+https://github.com/your-username/your-repo.git@tag-or-branch
        # или
        uv pip install git+https://github.com/your-username/your-repo.git@tag-or-branch
        ```

*   **Установка из локального дистрибутива**:
    1.  Сборка: `uv build` (создает `.whl` и `.tar.gz` в `dist/`)
    2.  Установка: `uv pip install dist/your_package-0.1.0-py3-none-any.whl`
        > **Примечание:** `uv add` не поддерживает установку из `.whl` файлов. Для этого всегда используйте `uv pip install`.

*   **Установка в режиме разработки**:
    ```bash
    uv pip install -e .
    # или для пользователей pip
    pip install -e .
    ```

## 5. Проверка и тестирование

После всех изменений необходимо проверить, что пакет работает корректно.

1.  **Создайте виртуальное окружение**: `uv venv`
2.  **Активируйте окружение**: `source .venv/bin/activate`
3.  **Установите пакет в режиме разработки**: `uv pip install -e .`
4.  **Запустите тестовую команду**: `python -c "from your_package import your_function; your_function()"`

Если все шаги проходят успешно, миграция завершена.
